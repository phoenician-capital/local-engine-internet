1. What this is

Local DeepSeek Flash has weights and a context window. It does not have a browser, a search index, or a PDF parser. Cloud models get those from vendor tools (Anthropic web_search, Gemini Google Search, Perplexity Sonar, DeepSeek cloud web_search).

This service is the replacement for that missing piece only.

  • It searches (SerpAPI / Tavily / Brave / optional SearXNG).
  • It fetches a URL and extracts readable text (HTML or PDF).
  • In chat, it lets the model call those as tools, then sends the results back to the Brain.

Inference, load-balancing, and GPU routing stay in ai-router on port 8080. Prompts and workflows stay in each product (PI, Earnings, portfolio, screening).

It never tells the model to “answer from your own knowledge.” If search is required and it fails, the caller gets an error.

Mode 1 is for Earnings rankers, EP smart_finder, PI Trustpilot/Reddit/IR scrapers — code that already decided to search. Mode 2 is for PI cheap path, portfolio DeepSeek, screening / CapIQ local desks — the model used to get a vendor web tool and will not have one on Flash.

3. The internet plugin (two layers)

This is the only product switch that matters.

3.1 Layer 1 — on or off

Master switch. When off:

  • POST /v1/search, /v1/fetch, /v1/research, GET /search → HTTP 503
  • Chat still works. It is a plain pass-through to the Brain. No tools. No search. No fetch. Our tool schemas are stripped if the client sent them.

When on, layer 2 applies.

WhereWhat
http://127.0.0.1:8090/uiButton
POST /v1/plugin {"enabled": true|false}Same switch, no restart
GET /v1/pluginStatus: enabled, intelligence, providers, search_ready
PLUGIN_ENABLED in .envValue at process start
phoenician_web.enabled: falseOff for that chat request only
Header X-Phoenician-Plugin: offOff for that request only

Global off always wins. A request cannot force the plugin on if the master switch is off.

search_ready is true only when at least one search key is configured and the plugin is on.

3.2 Layer 2 — intelligence (only if layer 1 is on)

The model decides whether this question needs the live web. That is policy: auto.

  • “What is 2+2?” — answer without searching.
  • “What did Nvidia report last quarter?” — call web_search, often then fetch_url.
phoenician_web.policyMeaning
auto (default)Model chooses. Tools are available. Maps to PI writers with offline fallback allowed.
requiredMust search. Maps to PI force_web_search=True. First turn with no tool call → one forced re-ask with tool_choice on web_search. Still no successful search → HTTP 424.
offPlugin stays on, this request is pass-through. Use this for streaming.

phoenician_tools: [] also means pass-through (opt out of tools).

Code: engine/plugin.py, engine/api/plugin.py, engine/api/ui.py.

4. Mode 1 — your code already wants the web

No LLM. You send a query or a URL. You get JSON. Plugin must be on, or you get 503.

4.1 Search — POST /v1/search

{
  "query": "Phoenician Capital",
  "num_results": 8
}

Returns hits[] (title, url, snippet, source, kind, also_from), providers_used, errors, confirmed (URLs seen by more than one provider).

Optional fields: providers, domain_mode, recency_days, on_empty (empty default, or error → 502 on zero hits).

4.2 Fetch — POST /v1/fetch

{"url": "https://example.com", "max_chars": 8000}

Returns the extracted page: title, text, final_url, is_pdf, tier, ok, error.

4.3 Search then fetch — POST /v1/research

Search, then fetch the top organic URLs (cross-confirmed first). Returns hits and pages.

4.4 SerpAPI drop-in — GET /search?q=&num=

Same JSON Earnings / EP / PI scrapers already parse: organic_results, answer_box, knowledge_graph, related_questions.

This path pins SerpAPI when that key exists (so answer box / knowledge graph survive). /v1/search and the model tools always mix every configured provider.

5. Mode 2 — the model decides mid-answer

File: engine/agent/loop.py. Non-streaming only. Both /v1/chat/completions and /chat/completions exist because SDKs disagree on /v1.

5.1 What happens on one request

  1. Client sends a normal OpenAI body.
  2. Engine checks layer 1 and layer 2 (engine/plugin.py).
  3. If the plugin is off, or policy is off, or phoenician_tools is []: strip phoenician_* and our tool schemas; forward the body to UPSTREAM_LLM_BASE_URL.
  4. If the plugin is on and policy is auto or required: inject web_search, fetch_url, search_and_read; prepend system rules (search when facts may have changed; do not invent URLs; treat ERROR: as failure); call the Brain.
  5. If the Brain returns tool_calls (or DSML markup in content that we recover): run those tools in parallel, append role: tool messages, call the Brain again. Repeat up to MAX_TOOL_ROUNDS (default 6).
  6. If policy is required and the first turn has no tool call: one forced re-ask (“You must call the web_search tool…”). Still no successful search → HTTP 424.
  7. When the Brain answers in prose, that JSON goes back to the client plus extras (plugin status, tool trace, sources, citation blocks, summed tokens).

Oldest tool outputs are compacted first if they exceed WEB_CONTEXT_BUDGET_CHARS (150k). Compacted stubs keep the URLs.

Caller Authorization is dropped. Upstream gets UPSTREAM_API_KEY. X-Priority is forwarded for ai-router.

5.2 Tools

ToolWhat happens
web_search(query, num_results=8, recency_days?)Parallel mix. Labeled hits. The model weighs them. The engine does not pick a “best” snippet.
fetch_url(url, max_chars=8000)Fetch + extract. First line is [PUBLIC_URL: url]. Only pass URLs search returned or the user gave.
search_and_read(query, top_n=3)Search, then fetch the top organics (confirmed URLs first). Saves a Flash round.

You do not need phoenician_tools for the default path. Omitted means all three. Empty list means no loop.

5.4 Streaming

stream: true cannot run the tool loop. HTTP 400 if the plugin would inject tools. Stream is allowed only as pass-through (plugin off or policy: off). phoenician_* fields are stripped before the Brain.

5.5 The Brain must emit tool calls

vLLM Flash will not produce structured tool_calls unless it was started with:

--tokenizer-mode deepseek_v4
--tool-call-parser deepseek_v4
--enable-auto-tool-choice
--reasoning-parser deepseek_v4

GET /capabilities reports brain_tool_calls_supported after a short startup probe (5s, does not block search). Mode 1 does not care. Mode 2 does.

If the model writes DeepSeek DSML in content instead of tool_calls, the engine recovers it: fullwidth-bar <｜DSML｜invoke>, open invoke without a closer, and tool▁calls▁begin blocks. Markup is stripped so it is not treated as the answer.

If the Brain is down, chat is 502. Mode 1 search still works if the plugin is on. There is no cloud LLM fallback.

6. Search mix

Every key you set is used in parallel. Results are blended. Not first-wins. Timeout 15s each, one retry on 429 / 5xx / timeout.

ProviderEnvWhat it adds
SerpAPISERPAPI_KEYGoogle rank, site:/filetype:, answer box, knowledge graph, related questions (first two), a little news. Enough alone. Paced 0.4s between calls.
TavilyTAVILY_API_KEYLonger excerpts. search_depth=advanced, no Tavily “answer” (we have our own Brain).
BraveBRAVE_API_KEYIndependent index, extra snippets, news.
SearXNGSEARXNG_URLOptional self-hosted.
Google CSEGOOGLE_API_KEY + GOOGLE_SEARCH_ENGINE_IDPin-only official-site fallback. Not in the default mix. Skip if the Custom Search project is suspended (403).

6.1 What happens on one query

  1. Fan-out all configured default providers (order: SerpAPI, Tavily, Brave, SearXNG).
  2. Same URL from two providers → one hit. SerpAPI stays source. If Tavily’s snippet is at least 40 characters longer, that text is kept. also_from lists the others.
  3. Organics are round-robin so one index cannot fill all eight slots.
  4. URLs seen by more than one provider go first. search_and_read and /v1/research fetch those first.
  5. One provider failing is skipped and listed in errors. Every provider failing is an error (Mode 1 → 502; the model sees ERROR: web_search unavailable (…). Do not present unverified facts as sourced.).

Zero hits after a successful provider call is “no results”, not a failure.

Dedup key: scheme + host without www + path without trailing slash, then snippet[:120].

6.3 Query helpers

engine/search/query.py can strip legal suffixes and build site: / filetype:pdf strings (Earnings style). The engine does not explode a ticker into 37 templates. Judgment stays with the caller or the model.

7. Fetch ladder

Port of Earnings tracker/summary/fetch.py, async. How a URL becomes text:

  1. Reject empty URL, social hosts, domain-mode deny list.
  2. Return cache hit if present (success 1800s, failure 120s).
  3. httpx — Chrome-like headers, age-gate cookies. Brotli is installed so Content-Encoding: br pages decode. Undecodable bodies are treated as a block.
  4. WAF / bot-challenge (401, 403, 406, 409, 429, 503 or challenge HTML) → curl_cffi Chrome impersonation.
  5. Thin HTML (<400 characters) or an IR-looking URL → Playwright (only if FETCH_MODE=full): expanders, tabs, EN/JP/PL results labels, spinner wait, data-pdf harvest, age-gate buttons, iframe snapshots.
  6. PDF — pdfplumber → PyMuPDF → pypdf → pdftotext → regex. First usable text wins. If all fail: a placeholder pointing at the real URL, not a fake transcript.
  7. SEC wrappers — EX-99.1 / EX-99.2 discovery, EDGAR User-Agent. The Earnings DeepSeek exhibit ranker was not ported. This is fetch, not judgment.

Caps: 8k characters HTML, 25k PDF, 25 MB PDF download, 20s document timeout.

FETCH_MODEUse
no_browser (.env.example)Search + static HTML/PDF. No Chromium.
httpx_onlyNo curl_cffi, no Playwright.
fullNeeds playwright install chromium. JS IR pages.

HTML extract: Trafilatura markdown (links and tables), then a simple HTML-to-text fallback (strip script/style, unescape entities, drop cookie chrome).

12. Run it

Python 3.12. One search key is enough (SERPAPI_KEY). Tavily and Brave join when you add their keys.

git clone https://github.com/phoenician-capital/local-engine-internet.git
cd local-engine-internet
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
# put SERPAPI_KEY= in .env
python -m engine

# second terminal
python scripts/check_search.py

That should print check_search ok. Then GET / should show search_ready: true.

Same thing: sh scripts/install.sh then python -m engine setup|run|check.

Docker: copy .env.example to .env, set the key, docker compose up --build. Optional profile searxng.

FETCH_MODE=full also needs playwright install chromium.

To print this paper: python docs/render_pdf.py.

16. What it does not do

  • Replace ai-router (inference, load balance, Brain keys)
  • Call Anthropic, Perplexity, or Gemini as a search backend
  • Require LangChain / LangGraph
  • Replace CapIQ, AlphaSense, Vertex / Gemini File Search, OpenAI embeddings / pgvector, FMP / yfinance, OpenAI TTS
  • Hide sources or pick “the” answer
  • Tell the model to invent facts when search is down
  • Stream the tool loop
  • Port Earnings’ DeepSeek ranker or 37-query templates
  • Put Google CSE in the default mix
  • Change the other product repos (PI still hardcodes DeepSeek cloud)
