1. What was done, in order

This is the full sequence, not a summary of “we built a search API.” Each step exists because the previous one produced a constraint.

1.1 Create the repository

The GitHub repository phoenician-capital/local-engine-internet was created under the organization so every team can use it later. Owner is the org. An initial README stated the intent: a dedicated internet layer for local LLMs.

1.2 Clone every phoenician-capital project locally

Every organization repository was cloned into org-repos/ (gitignored, never committed). The point was research, not a monorepo. Those clones were read in place. Nothing from them was copied into git except the ported logic, rewritten into this service’s own packages.

Where the two disagree on fetch or SERP details, the surgical file wins.

1.7 Plan, then implement

A build plan was written around one law: do not confuse pipeline-directed internet (code already decided to search) with LLM-directed internet (the model decides mid-generation). Then the plan was implemented in this repo: scaffold, search providers, fetch ladder, extract, tools, agent loop, HTTP API, tests, README. The plan file itself was not edited.

1.8 Verify, commit, push

43 unit tests passed (pytest + respx, no live keys required). The work was committed as 96315a1 and pushed to origin/main. Secrets and org-repos/ were not committed.

2. The problem this repo exists to solve

The company is moving inference to a local DeepSeek V4 Flash Brain on vLLM, reached through ai-router on port 8080. A local model has weights and a context window. It does not have a browser, a SERP, or a PDF parser.

Today, “the model looked it up” is almost always a vendor server tool:

  • Anthropic web_search_20250305 — DD writing, screening analyst/memo, portfolio debate, CapIQ chat/auditor
  • Gemini GoogleSearch — PI call_gemini_web, Earnings news, dcf--app
  • Perplexity Sonar — PI prefetch, red flags, TAM, technicals, H2H, screening news
  • DeepSeek cloud /responses web_search — PI cheap workflow only
  • Z.ai web_search — CapIQ GLM desks
  • SerpAPI — Earnings calendar/extract, PI Trustpilot/Reddit/IR, ai-router snippets
  • Tavily — ai-router only

ai-router already has a thin web_search tool (SerpAPI + Tavily snippets, max 3 rounds, no page fetch, no ranking, no citations). If no keys are set, it tells the model to answer from its own knowledge. Research callers treat that as a bug.

Setting DEEPSEEK_BASE_URL to the router does not enable search. Callers must send phoenician_tools. In PI, that base URL is still hardcoded to https://api.deepseek.com.

This repo is internet only. It is not a second inference proxy. Load-balancing, Brain auth, and GPU routing stay in ai-router. Prompts and workflows stay in each product.

3. The one distinction the whole engine is built around

There are two ways the organization touches the internet. Mixing them produces the wrong product: either the model is forced to search when code already did, or code is asked to “be smart” when the model should decide.

Mode 1 — pipeline-directedMode 2 — LLM-directed
Who decidesApplication code already knows it needs the webThe model decides mid-answer
LLM’s jobJudge or extract after search (Earnings ranker)Choose query, choose URL, write with sources
TodaySerpAPI from Python/JS, then fetch in EarningsVendor server tools (Claude / Gemini / Perplexity / DeepSeek cloud)
This enginePOST /v1/search, /v1/fetch, /v1/research, GET /searchPOST /v1/chat/completions with an agentic tool loop
Typical callersEarnings, EP smart_finder, PI Trustpilot/Reddit/IRPI cheap path, portfolio DeepSeek, screening / CapIQ local desks

Same search providers and fetch ladder underneath. Different entry points. Never mixed inside one handler.

Mode 2 is the product. Local Flash has no vendor web tool. Mode 1 is exposed so pipelines that already decided to search do not have to pretend they are an agent.

5. Findings that constrained the design

  1. Almost nothing talks to ai-router. Apps call cloud SDKs. The intended hook is DEEPSEEK_BASE_URL.
  2. Local Brain is Flash only. Earnings and some PI paths call deepseek-v4-pro. Do not silently route Pro to a Flash-only Brain.
  3. Web search is vendor-native. Local Flash has none of those tools unless this engine (or a later router client) provides them.
  4. Cheap PI path is a monkey-patch of Claude/Gemini/Perplexity onto DeepSeek. DCF streaming and Gemini File RAG are not patched.
  5. Fail policies disagree. Screening memo can fail-open to templates. PI Section 8 DCF raises. Router search fail-opens to memory. The engine default is fail-closed for research.
  6. Snippets-only will fail DD, CapIQ research, and Earnings. Fetch + extract had to ship on day one.
  7. The company already has a fetch engine in Earnings (httpx → curl_cffi → Playwright → PDF/SEC). Port it. Do not invent a new one.
  8. SerpAPI is richer than title/snippet/link. EP calendar quality depends on answer_box, knowledge_graph, and the first two related_questions. The router throws those away. This engine keeps them.
  9. vLLM Flash must be launched with tool parsers or it will not emit structured tool_calls. Streaming tool calls leak DSML into arguments.
  10. PI writers parse two citation shapes. A replacement that emits only one of them loses hyperlinks.
  11. Deny lists are per-mode. Earnings fetches SEC. PI IR discovery must not treat sec.gov as the company’s IR site.

6. Topology decision

The engine sits in front of ai-router on port 8090.

Company apps
    │  OpenAI chat-completions body
    │  (optional phoenician_tools / phoenician_web)
    ▼
local-engine-internet :8090
    ├─ Mode 2  /v1/chat/completions  → tool loop → UPSTREAM_LLM_BASE_URL (ai-router :8080) → vLLM Flash
    ├─ Mode 1  /v1/search  /v1/fetch  /v1/research
    └─ Compat  GET /search  (SerpAPI-shaped JSON)
         │
         ├─ search providers (Brave, SerpAPI, Tavily, SearXNG, optional CSE)
         └─ fetch ladder (httpx → curl_cffi → Playwright → PDF / SEC)

Apps that only change DEEPSEEK_BASE_URL to this engine get “search when needed” because the default policy is auto and the three tools are injected. That is a deliberate product difference from ai-router, which is opt-in via phoenician_tools. Pass-through without tools is phoenician_web.policy: "off".

ai-router is unchanged in this work. Its run_web_search can later become a thin HTTP client to POST /v1/search. That wiring is documented, not executed here.

9. Data contracts

9.1 Hit

Defined in engine/search/base.py. Sources stay labeled. The model weighs them; the engine does not pick a “best” snippet.

{
  "title": str,
  "url": str,
  "snippet": str,
  "source": "serpapi" | "brave" | "tavily" | "searxng" | "google_cse",
  "kind": "organic" | "answer_box" | "knowledge_graph" | "related_question",
  "position": int,
  "date": str | null,
  "query": str
}

Dedup key: canonical URL (scheme + host without www + path without trailing slash), then snippet[:120].

9.2 Page

Defined in engine/fetch/ladder.py.

{
  "url": str, "final_url": str, "title": str, "text": str,
  "content_type": str, "is_pdf": bool,
  "tier": "httpx" | "curl_cffi" | "playwright" | "sec" | "cache",
  "ok": bool, "error": str | null
}

9.3 Chat request extras (stripped before upstream)

  • phoenician_tools — subset of web_search, fetch_url, search_and_read. Omitted means all three (engine default). Empty list means no loop.
  • phoenician_web — { policy, max_search_uses, max_fetches, max_rounds, fetch_mode, domain_mode, providers, web_context_budget_chars }

Caller Authorization is dropped. Upstream receives UPSTREAM_API_KEY. X-Priority is forwarded for ai-router.

9.4 Chat response extras

  • phoenician_tool_trace — [{tool, arguments}, …] identical idea to ai-router
  • phoenician_usage_total — summed prompt/completion/total across every upstream round
  • phoenician_sources — URLs actually returned by search or fetch
  • phoenician_citations_block — both PI citation forms
  • phoenician_search_failed — true if a provider raised

10. Search method

Providers are enabled only by the presence of keys. Adding a key later changes nothing else. Per-provider timeout is 15 seconds. One failure is skipped and recorded. If every attempted provider fails, or none are configured, the engine raises SearchUnavailable with a fail-closed string — it does not invent results and does not tell the model to use training data.

Default fan-out order when the caller does not pin providers: Brave, SerpAPI, Tavily, SearXNG (whichever are configured). Google CSE is pin-only (official-website fallback), not part of the default fan-out even if keys exist.

10.1 SerpAPI — engine/search/serpapi.py

GET https://serpapi.com/search with engine=google, hl=en, gl=us. Key from SERPAPI_KEY or SERPAPI_API_KEY.

Parser (EP smart_finder):

  • organic: title, snippet, link, position, date; skip duplicate URL or snippet[:120]
  • answer_box: answer or snippet + link, kind answer_box
  • knowledge_graph: title + description + attribute values, kind knowledge_graph
  • related_questions: first two only

Recency maps to tbs=qdr:d|w|m|y. Consecutive queries are paced 0.4s (disable in tests via SERPAPI_PACE_SECONDS=0). Site-restricted empty responses are a valid empty set, not a burned failure — that pacing/budget rule lives in EP’s multi-query loop; a single /v1/search just returns empty hits from that provider.

10.2 Brave — engine/search/brave.py

GET https://api.search.brave.com/res/v1/web/search with header X-Subscription-Token. Hits from web.results[] (title, url, description, age). Recency: freshness=pd|pw|pm|py.

10.3 Tavily — engine/search/tavily.py

Port of the router client. POST https://api.tavily.com/search with api_key, query, max_results, optional days.

10.4 SearXNG — engine/search/searxng.py

GET {SEARXNG_URL}/search?q=&format=json&categories=general. Optional compose profile searxng.

10.5 Google CSE — engine/search/google_cse.py

PI official-website fallback. GET https://www.googleapis.com/customsearch/v1?key=&cx=&q=&num= (num capped at 10, timeout at least 20s). Items: link, title, snippet. Same GOOGLE_API_KEY also unlocks Gemini in other apps — this module is CSE only.

10.6 Merge — engine/search/merge.py

  1. Resolve provider list (pin or default fan-out ∩ configured).
  2. asyncio.gather all providers.
  3. Collect hits and errors. Keep raw SerpAPI extras for the compat endpoint.
  4. Apply domain_mode deny list.
  5. Dedup. Keep up to num_results organics plus all specials (answer box / KG / related).
  6. Format for the model as labeled blocks: [serpapi:organic], [brave:organic], etc.

on_empty=error raises if there are zero hits after a successful provider call. Default is empty (scrapers).

10.7 Query hygiene — engine/search/query.py

Port of Earnings build_simple_queries:

  • Strip legal suffixes (PLC, Inc, Ltd, Corp, S.A., ASA, …)
  • site:{host} and filetype:pdf builders
  • Aggressive PDF-oriented query list: quoted company + quarter/year, ticker, IR domain, q4cdn/mziq, cap 15, deduped

The engine does not explode into 37 templates. Judgment stays with the caller (ranker or model).

11. Fetch method

Canonical source: Earnings tracker/summary/fetch.py, rewritten async-first for FastAPI. FETCH_MODE is full (all tiers), no_browser (httpx + curl_cffi), or httpx_only (Lambda-style, no Chromium).

11.1 Ladder order — engine/fetch/ladder.py

  1. Reject empty URL, social hosts, domain-mode deny list.
  2. Return process-wide cache hit if present (success TTL 1800s, failure TTL 120s, max 256 entries).
  3. Direct PDF (non-SEC): httpx with document headers and same-origin Referer; on WAF statuses {401,403,406,409,429,503} escalate to curl_cffi impersonate chrome; then Playwright request stack after warming the origin.
  4. IR-looking URL (ir. or “investor” in the URL) and mode=full: Playwright first, because static HTML is often boilerplate.
  5. Otherwise httpx with Chrome-like headers, Accept-Language, Sec-Fetch-*, gzip/br, and age-gate cookies (age_verified, over18, legal_age, is_over_18).
  6. If the body looks like a WAF challenge (PI markers in the first 5 kB: “please verify you are a human”, Cloudflare, Sucuri, Distil “pardon the interruption”, “are you a robot”, “403 forbidden”) treat it as a block and escalate.
  7. SEC wrapper URLs (sec.gov, or Yahoo cdn.yahoofinance.com + sec-filings) go through exhibit discovery.
  8. Thin HTML (< 400 chars) escalates to Playwright when mode=full.
  9. Extract, cap (8k HTML / 25k PDF unless the caller set max_chars), cache, return Page.

PDF detection: magic bytes %PDF, or content-type containing pdf unless the body is HTML disguised as PDF.

Limits copied from Earnings: document timeout 20s, max PDF 25 MB, headless render 15s, thin threshold 400 chars.

11.2 Extract — engine/fetch/extract.py

Trafilatura first (markdown, links and tables, multilingual). If it yields nothing, Earnings html_to_text: strip script/style/svg/head; br/p/div/li/tr/h* → newline; unescape nbsp/amp/lt/gt/quot/euro/pound/yen; drop Cookie/Privacy/Accept Cookies chrome. Title from Trafilatura metadata or <title>. Canonical from metadata or rel=canonical.

11.3 PDF chain — engine/fetch/pdf.py

pdfplumber → PyMuPDF (fitz) → pypdf (strict=False) → pdftotext/poppler → raw regex of readable strings. First parser that yields usable text wins. If all fail, placeholder: “This document is a PDF report available at: {url}” — never a hallucinated transcript.

11.4 SEC — engine/fetch/sec.py

Compliant User-Agent is required or EDGAR 429s. Default SEC_EDGAR_USER_AGENT identifies LocalEngineInternet + phoeniciancapital.com. Wrapper pages are not the earnings release. The handler:

  • Regex-extracts EX-99.1 / EX-99.2 / exhibit hrefs; prefers PDF then EX-99.1
  • On Yahoo wrappers, ranks sibling .htm/.pdf links by “earnings release”, “presentation”, …
  • Fetches up to five exhibits with the SEC UA
  • Falls back to wrapper body extraction and embedded <DOCUMENT><TYPE>EX-99.1 blocks

The Earnings DeepSeek exhibit ranker was not ported. This is fetch, not judgment.

11.5 JS IR interaction — engine/fetch/js_interact.py

Matched by accessible name / role, never by company. Ported constants:

  • Expanders: load/show/view more, もっと見る, 一覧, すべて, さらに表示, 過去
  • Tabs: [role=tab], Bootstrap/ARIA accordions
  • Results labels: financial results, 決算, 四半期, 有価証券報告書, 決算短信, 適時開示, raporty okresowe
  • Hidden URL attrs: data-url, data-pdf, data-file, …
  • Doc hosts without .pdf: xj-storage.jp, irpocket, q4cdn, mziq, cloudfront /documents/
  • Wait for spinners: .loading, [aria-busy=true], …
  • Age-gate buttons: “I am 18”, Enter, Confirm, …
  • Iframe snapshots (Investis/EQS RNS widgets) with links rewritten absolute against the frame URL

Snapshots after each state change are concatenated so a tab click that replaces the DOM does not lose earlier PDF links.

12. Tools the model is allowed to call

OpenAI function-calling schemas in engine/tools/schemas.py. vLLM Flash must emit tool_calls in that shape.

12.1 web_search

Arguments: query (required), num_results, recency_days. Description tells the model results are raw and unlabeled-by-quality — weigh them itself. Output is labeled text, not JSON hidden from the model.

12.2 fetch_url

Arguments: url (absolute http/https), max_chars. Output always starts with [PUBLIC_URL: …] so PI’s URL rule can be obeyed. Only pass URLs search returned or the user gave.

12.3 search_and_read

Arguments: query, top_n (default 3). One round: search, then fetch organic URLs. Exists because Flash has a low useful tool-round budget; the router’s max of 3 was too low once fetch is a tool, so the engine default is 6 rounds and this composite saves one hop.

12.4 Dispatch — engine/tools/execute.py

ToolExecutor holds the budget, domain mode, fetch mode, optional provider pin, and the accumulating sources list. Over-budget calls return an ERROR string. Invalid URLs return an ERROR string. Unknown tool names return an ERROR string. Nothing invents a page.

12.5 DSML fallback — engine/tools/dsml_fallback.py

Known Flash/vLLM failure: tool_calls is empty but content contains markup. Recovered forms:

  • Fullwidth-bar DSML: <｜DSML｜invoke name="web_search"> with parameter tags (ASCII | also accepted)
  • Open invoke without a closer (start-token omission at long context)
  • DeepSeek tokenizer blocks: tool▁calls▁begin / tool▁sep + JSON fence

Recovered calls are written back onto the assistant message and the markup is stripped so a later reader does not treat DSML as the answer.

13. Mode 2 agentic loop — step by step

File: engine/agent/loop.py. Non-streaming only.

  1. Strip phoenician_tools and phoenician_web.
  2. If policy is off or tools list is empty: single post_completion to ai-router. Return. No guidance injected.
  3. Otherwise inject the three (or requested) OpenAI tool schemas. Default tool_choice=auto.
  4. Prepend PI web system guidance (or merge into the caller’s existing system message): use tools when facts may have changed; prioritize official filings; never fabricate URLs; if a tool result starts with ERROR, treat it as a hard failure; no “Sources” appendix; no preamble.
  5. POST to UPSTREAM_LLM_BASE_URL (ai-router), timeout 300s, forward X-Priority, send upstream key.
  6. Read tool_calls. If empty, run DSML recovery.
  7. If still empty and policy is required and we have not already re-asked: append a user nudge (“You must call the web_search tool before answering. Search now.”), set tool_choice forced on web_search, POST once more.
  8. If still empty after that re-ask (or search never succeeded): raise RequiredSearchFailed → HTTP 424.
  9. Execute every tool call of the round in parallel (asyncio.gather). Enforce max_search_uses / max_fetches.
  10. Append role: tool messages. Compact oldest tool outputs first if the running total exceeds WEB_CONTEXT_BUDGET_CHARS (150k). Compacted stubs keep the URLs.
  11. Repeat up to MAX_TOOL_ROUNDS (default 6).
  12. Collect every URL actually returned into phoenician_sources. Build both citation blocks. Return the last upstream JSON plus extras.

The model is told it may hyperlink only those URLs. A broken link is worse than no link. That sentence is from PI’s production system message, not invented here.

14.1 Stream rule

stream:true plus tools / default auto loop → HTTP 400, same sentence as ai-router. Stream is proxied only when policy is off (or tools explicitly empty). Final-answer SSE after the loop is phase 2, not built.

14.2 Compat shape

GET /search pins SerpAPI when that key exists so answer_box / knowledge_graph survive for Earnings/EP. Otherwise it synthesizes the same keys from merged Hits. Scrapers already parse organic_results[].title|snippet|link|position.

14.3 Upstream errors

Brain down or HTTP error from ai-router → 502. No cloud LLM fallback. That is intentional and matches the router’s local-only law.

14.4 Startup canary

Unless RUN_CANARY_ON_STARTUP=false, lifespan sends a tiny tool-forced prompt to upstream. If no tool_calls (and no recoverable DSML), it logs the four required vLLM flags. GET /capabilities reports brain_tool_calls_supported. Treat the engine as not done on a real box until that is true.

15. Fail-closed policy

The router string “Answer from your own knowledge instead, and say so.” is never emitted. Tests assert the substring own knowledge is absent.

19. What this engine deliberately does not do

  • Replace ai-router (inference, load balance, Brain keys)
  • Call Anthropic, Perplexity, or Gemini as a search backend
  • Require LangChain / LangGraph
  • Replace CapIQ (Selenium, credentials), AlphaSense, Vertex / Gemini File Search, OpenAI embeddings / pgvector, FMP / yfinance, OpenAI TTS, investor-portal PDF extract, Linker qualitative score
  • Hide sources or pre-rank “the” answer
  • Tell the model to hallucinate when search is down
  • Stream tool calls (known DSML leak)
  • Port Earnings’ DeepSeek ranker or 37-query templates
  • Auto-include Google CSE in every fan-out
  • Wire the other product repos (documented only)
