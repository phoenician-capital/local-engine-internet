1. What the process does

One FastAPI process. It does not load a model. It talks to search APIs, downloads pages, and (in chat) sits between the client and an upstream LLM.

client
   │
   ▼
engine :8090
   ├── POST /v1/search | /v1/fetch | /v1/research
   ├── GET  /search
   └── POST /v1/chat/completions  →  UPSTREAM_LLM_BASE_URL
                                         (default :8080)

Mode 1 — you send a query or a URL. No LLM in the hop.

Mode 2 — you send chat messages. The engine may inject tools, run them, and call the LLM again until it answers in prose.

Same search and fetch code under both. If the plugin is off, Mode 1 returns 503 and Mode 2 is a pass-through (no tools).

2. Plugin — on/off, then the model chooses

Code: engine/plugin.py, runtime.plugin_enabled, engine/api/plugin.py, engine/api/ui.py.

Layer 1 — enabled or disabled

A boolean. Off means no search and no fetch.

  • Mode 1 → HTTP 503
  • Mode 2 → body forwarded to the LLM with phoenician_* removed and this engine’s tools stripped

Set it at /ui, POST /v1/plugin {"enabled": true|false}, or PLUGIN_ENABLED at startup. One request can turn it off with phoenician_web.enabled: false or header X-Phoenician-Plugin: off. A request cannot turn it on if the process switch is off.

GET /v1/plugin returns enabled, intelligence, providers, search_ready. Ready = at least one search key and plugin on.

Layer 2 — only when layer 1 is on

phoenician_web.policy (or DEFAULT_WEB_POLICY):

ValueBehaviour
autoTools are injected. The model decides whether to call them.
requiredMust complete a successful web_search. One forced re-ask if the first turn has no tool call. Still none → HTTP 424.
offPass-through this request. Needed for stream: true.

phoenician_tools: [] is also pass-through.

3. Mode 1 — search / fetch / research

Code: engine/api/primitives.py, engine/api/compat.py. Plugin must be on.

POST /v1/search

{"query": "Phoenician Capital", "num_results": 8}

Optional: providers, domain_mode, recency_days, on_empty (empty or error).

Returns hits, providers_used, errors, confirmed (URLs seen by more than one provider). No providers or all failed → 502.

POST /v1/fetch

{"url": "https://example.com", "max_chars": 8000}

Returns title, text, final_url, is_pdf, tier, ok, error.

POST /v1/research

Search, then fetch the top organic URLs (cross-confirmed first). Returns hits and pages.

GET /search?q=&num=

JSON shaped like SerpAPI: organic_results, answer_box, knowledge_graph, related_questions. Pins SerpAPI when that key exists. /v1/search and the chat tools always mix every configured provider.

4. Mode 2 — chat tool loop

Code: engine/api/chat.py → engine/agent/loop.py. Routes: /v1/chat/completions and /chat/completions.

One request

  1. Parse JSON. Read plugin + policy + phoenician_tools.
  2. If stream: true and the loop would run → 400. Stream is pass-through only (plugin off or policy off). phoenician_* is stripped before upstream.
  3. Pass-through: one POST to UPSTREAM_LLM_BASE_URL. No system guidance, no tools from this engine.
  4. Loop: inject web_search, fetch_url, search_and_read (or the subset in phoenician_tools). Prepend the system rules in engine/agent/prompts.py. POST to the LLM.
  5. If the reply has tool_calls, or DSML / tool▁calls markup in content (engine/tools/dsml_fallback.py), run those tools in parallel, append role: tool, POST again. Cap: MAX_TOOL_ROUNDS (6). Over WEB_CONTEXT_BUDGET_CHARS (150k), oldest tool text is compacted; URLs stay.
  6. Policy required and no successful search → 424.
  7. Return the last LLM JSON plus phoenician_plugin, phoenician_tool_trace, phoenician_sources, phoenician_citations_block, phoenician_usage_total, phoenician_search_failed.

Client Authorization is dropped. Upstream gets UPSTREAM_API_KEY. X-Priority is forwarded. LLM down → 502.

The upstream model must emit OpenAI tool_calls. For vLLM DeepSeek Flash that means:

--tokenizer-mode deepseek_v4
--tool-call-parser deepseek_v4
--enable-auto-tool-choice
--reasoning-parser deepseek_v4

GET /capabilities reports brain_tool_calls_supported after a 5s startup probe. Mode 1 does not use this.

Tools — engine/tools/

5. Search

Code: engine/search/. Every configured provider runs in parallel. 15s each, one retry on 429 / 5xx / timeout (httputil.py).

FileEnvWhat it returns
serpapi.pySERPAPI_KEYGoogle organics, answer box, knowledge graph, 2 related questions, 2 news as organics. 0.4s pace between calls. JSON error field is a failure.
tavily.pyTAVILY_API_KEYLonger excerpts. Query trimmed to 400 chars. include_answer=false.
brave.pyBRAVE_API_KEYWeb results + extra snippets + 2 news.
searxng.pySEARXNG_URLSelf-hosted JSON.
google_cse.pykey + cxPin-only. Not in the default mix.

merge.py after fan-out:

  1. Skip a failed provider; record it in errors. All failed → SearchUnavailable (Mode 1: 502; tool: ERROR: web_search unavailable (…). Do not present unverified facts as sourced.).
  2. Apply domain_mode.
  3. Same URL → one hit. Lower PROVIDER_PRIORITY keeps source (SerpAPI first). Snippet replaced if the other is ≥40 characters longer. also_from lists the rest.
  4. Organics round-robin: SerpAPI, Tavily, Brave, SearXNG. Cross-confirmed URLs first.
  5. Specials (answer box / KG / related) kept beside the organic list.

Dedup key: scheme + host without www + path without trailing slash, then snippet[:120].

query.py: strip legal suffixes; build site: / filetype:pdf; optional earnings-style query list. The engine does not auto-explode a ticker into many queries unless the caller uses those helpers.

domain_mode (engine/fetch/policy.py):

ModeDropped
general_researchSocial / spam hosts
ir_discoveryAggregators + IR PDF blocklist including sec.gov
earnings_docSocial only; sec.gov allowed

Hit shape (base.py): title, url, snippet, source, kind, position, date, query, also_from.

6. Fetch

Code: engine/fetch/. Entry: fetch_url() in ladder.py.

  1. Reject empty URL, social hosts, domain-mode deny list.
  2. Cache (cache.py): success 1800s, failure 120s, max 256 entries.
  3. httpx — Chrome-like headers, age-gate cookies. Only advertise encodings we can decode. Brotli garbage → treat as block.
  4. WAF / challenge (401, 403, 406, 409, 429, 503 or challenge HTML) → curl_cffi Chrome impersonation.
  5. Thin HTML (<400 chars) or IR-looking URL → Playwright if FETCH_MODE=full (js_interact.py: expanders, tabs, EN/JP/PL labels, spinners, data-pdf, age-gate, iframes).
  6. PDF (pdf.py): pdfplumber → PyMuPDF → pypdf → pdftotext → regex. All fail → placeholder with the real URL.
  7. SEC wrappers (sec.py): EX-99.1 / EX-99.2 links, EDGAR User-Agent.

Extract (extract.py): Trafilatura markdown, then HTML-to-text fallback. Caps: 8k HTML, 25k PDF, 25 MB download, 20s timeout.

FETCH_MODE: no_browser (httpx + curl_cffi), httpx_only, full (needs Chromium).

Page shape: url, final_url, title, text, content_type, is_pdf, tier, ok, error.

9. How to run

python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env          # set SERPAPI_KEY
python -m engine              # :8090
python scripts/check_search.py

Clients: OpenAI-compatible base http://127.0.0.1:8090/v1, key local if unset. DeepSeek-style base without /v1: http://127.0.0.1:8090.

Docker: docker compose up --build. FETCH_MODE=full needs playwright install chromium.

PDF of this file: python docs/render_pdf.py.
