A short paper you can send. How the service works, what we tested on 9 September 2026, and the live numbers DeepSeek Flash produced after searching and reading Apple’s own filings. How to run it is at the end. No cloud writing models. Same Flash you will run in the datacenter.

Engine: http://127.0.0.1:8090
Model: deepseek-v4-flash (DeepSeek API today · local Brain tomorrow)
Search: SerpAPI + Tavily
Date of run: 9 September 2026, 10:50–10:55 UTC
Internals (full code map): Local-LLM-Internet-Engine-Method.pdf

1. How it works

Company apps already talk to DeepSeek with POST /v1/chat/completions (messages, tools, tool_calls). This service sits on port 8090 and speaks that same DeepSeek / vLLM wire format. It does not load model weights. It searches the web, downloads pages, and — in chat — sits in front of DeepSeek Flash.

Analyst / PI / portfolio app
        │
        ▼
local-engine-internet  :8090
   ├── search + fetch     SerpAPI, Tavily  (Brave later)
   └── chat + tools       DeepSeek Flash
                                │
                     today:  api.deepseek.com
                     later:  ai-router :8080  (same model name)

Mode 1 — the pipeline already decided to search. POST /v1/search, /v1/fetch, /v1/research. No model in the hop.

Mode 2 — the user sends a question. Flash may call web_search and fetch_url. The engine runs those tools and asks Flash again until it answers in prose. Sources stay labeled. If search is required and fails, the HTTP status is 424 — it does not invent numbers from training data.

When the datacenter Brain is up, change one setting: UPSTREAM_LLM_BASE_URL=http://127.0.0.1:8080. Apps keep pointing at http://127.0.0.1:8090/v1. You stop using Claude / GPT / Gemini / Perplexity as the writer. You still use search APIs (Google via SerpAPI, Tavily). Those are indexes, not models.

5. What this means for the datacenter

today     engine :8090  →  api.deepseek.com     →  deepseek-v4-flash
later     engine :8090  →  ai-router :8080      →  same Flash, local weights

vLLM flags the Brain needs so Flash emits structured tool_calls (same JSON DeepSeek’s own API uses):

--tokenizer-mode deepseek_v4
--tool-call-parser deepseek_v4
--enable-auto-tool-choice
--reasoning-parser deepseek_v4

One cloud quirk we already handled: DeepSeek V4 thinking mode rejects a forced tool_choice (the canary and policy: required). The engine sends thinking: {type: disabled} only when the upstream host is api.deepseek.com. Local vLLM is unchanged.

Not in this run: Brave key, self-hosted SearXNG, the metal Brain on :8080. None of those block the path above.

6. How to use it

Repo: https://github.com/phoenician-capital/local-engine-internet. Python 3.12. You need one search key to start (SerpAPI is enough). Chat also needs DeepSeek — either the public API today, or ai-router on :8080 when the local Brain is up.

Install and start

git clone https://github.com/phoenician-capital/local-engine-internet.git
cd local-engine-internet
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
# edit .env — see the table below
python -m engine

When it is up: toggle http://127.0.0.1:8090/ui · HTTP docs http://127.0.0.1:8090/docs · welcome JSON http://127.0.0.1:8090/.

What to put in .env

VariableWhat you set
SERPAPI_KEYRequired to search. Enough by itself.
TAVILY_API_KEYOptional. Longer excerpts. Joins the mix automatically.
BRAVE_API_KEYOptional. Independent index.
UPSTREAM_LLM_BASE_URLChat only. Today: https://api.deepseek.com. Later: http://127.0.0.1:8080.
UPSTREAM_API_KEYDeepSeek API key, or ROUTER_API_KEY for ai-router. Leave empty if the Brain has no key.
UPSTREAM_MODELdeepseek-v4-flash
PLUGIN_ENABLEDtrue (default). Master switch; you can also flip it at /ui.
ENGINE_API_KEYLeave empty on your laptop. Set a secret if the port is on a network.

Do not commit .env. Never put keys in Slack or this PDF.

Search only (no model)

Use this from a pipeline, a script, or curl. The plugin must be on (default).

curl -s http://127.0.0.1:8090/v1/search \
  -H 'Content-Type: application/json' \
  -d '{"query":"Apple Inc latest 10-Q","num_results":8}'

curl -s http://127.0.0.1:8090/v1/fetch \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com"}'

curl -s http://127.0.0.1:8090/v1/research \
  -H 'Content-Type: application/json' \
  -d '{"query":"Apple Inc latest 10-Q","fetch_top":2}'

# Prove Mode 1:
python scripts/check_search.py --engine

Search returns hits, providers_used, confirmed (URLs seen by more than one index). Fetch returns page text, tier, ok. Research = search then fetch the top URLs (confirmed first).

Chat with search (the usual way)

Point any DeepSeek / vLLM client at this engine instead of api.deepseek.com. Base URL http://127.0.0.1:8090/v1. API key local if you left ENGINE_API_KEY empty. Model deepseek-v4-flash.

from openai import OpenAI
client = OpenAI(base_url="http://127.0.0.1:8090/v1", api_key="local")
r = client.chat.completions.create(
    model="deepseek-v4-flash",
    messages=[{"role": "user", "content": "What was Apple last reported quarterly revenue? Cite a live URL."}],
)
print(r.choices[0].message.content)
print(r.model_extra.get("phoenician_tool_trace"))   # or r.to_dict()

The snippet above uses the common Python chat client (openai package) only as an HTTP helper — the model is still Flash. DeepSeek SDK: same messages, base_url="http://127.0.0.1:8090" (no /v1). Cursor / Continue: custom host http://127.0.0.1:8090/v1, model deepseek-v4-flash.

Optional extra on the JSON body (the engine strips it before Flash sees it):

{
  "phoenician_web": {
    "policy": "auto"
  }
}
policyWhen to use it
auto (default)Flash decides. “What is 2+2?” stays offline. A dated company question searches.
requiredResearch desks. Must complete a successful search, or HTTP 424.
offThis request only — no tools. Needed for stream: true.

If the reply JSON includes phoenician_tool_trace, Flash searched or fetched. phoenician_sources lists the URLs. Treat a tool result that starts with ERROR: as a hard failure — do not treat it as a fact.

Turn the internet off for everyone at /ui or POST /v1/plugin {"enabled": false}. Chat then becomes a plain pass-through to Flash. One request can turn it off with header X-Phoenician-Plugin: off.
